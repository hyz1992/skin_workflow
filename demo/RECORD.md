# 商城修仙风换皮实录

本案例从一张台球游戏商城截图出发，依次完成 **母版设计 → 独立切图 → 离线网页原型**。用户主要负责提供原图与风格、查看结果、决定是否进入下一阶段；AI 使用项目中的三个 skill 完成对应工作。

记录日期：2026-09-17。以下引用保留用户原始提示词；操作说明是对实际执行过程的整理。AI 发给图像工具的扩展提示词另行保存，不与用户原话混写。

## 一眼看懂怎么用

| 阶段 | 用户提供 / 发出指令 | AI 使用的 skill | 用户查看的主要结果 |
| --- | --- | --- | --- |
| 1. 母版设计 | 原始截图 + 页面用途 + 目标风格 | `ui-skin-design` | [整页母版](shop-xianxia/design-r01/master.png) |
| 2. 切图资源 | 选定母版，要求切图 | `ui-skin-assets` | [逐件切图审核页](shop-xianxia/assets-r01/asset-preview.html) |
| 3. 网页原型 | 选用切图，要求组装网页 | `ui-skin-prototype` | [可交互网页原型](shop-xianxia/prototype-r01/prototype.html) |

本例没有要求用户手写组件清单、切图坐标或技术文档，这些由 AI 随阶段整理。原始对话也没有手动输入 `$skill` 名称，AI 根据任务选择了对应 skill。需要明确指定时，可在请求中直接写出 skill 名称。

其他页面可以照着下面三段原话使用：第一段替换截图路径、页面用途和目标风格，后两段在查看本轮结果后发出。三个 skill 已在项目根目录的 `.agents/skills/` 中；迁移技能到其他项目时，把三个 skill 目录一起复制，**不需要把本案例的过程资料也作为运行依赖带过去**。

## 阶段一：母版设计

### 用户原始提示词

> 现在可以直接开始换皮了是吧，我已经在项目中放了一张截图：demo/商城-原始.jpg
> 这是一个台球游戏的商城弹窗，请根据这张截图，对该商城弹窗进行换皮母版设计，整体风格为修仙风格。

### AI 对应操作

1. 使用 `ui-skin-design`，读取原始截图，盘点商城现有内容：充值标题、钻石/金币/体力页签、VIP 等级与进度、贵族特权、客服、关闭按钮、商品和价格、消费提示。
2. 保留原有货币名称和五档已知钻石商品：`10 / ¥1`、`30 / ¥3`、`60 / ¥6`、`180 / ¥18`、`300 / ¥30`。没有依据的其他商品或业务规则不补造。
3. 将视觉设计为青玉墨青底板、鎏金云纹边框、宣纸水墨卡片，并加入竹叶、莲花装饰。五张商品卡完整陈列。
4. 使用内置图像工具生成整页母版，查看画面、固定文字和组件是否完整；保存设计说明、组件/状态清单和实际生图提示词。

### 操作产出

| 文件 | 用途 |
| --- | --- |
| [商城-原始.jpg](商城-原始.jpg) | 用户提供的原始截图，2400×1080 |
| [design-r01/master.png](shop-xianxia/design-r01/master.png) | 修仙风整页母版，实际生成尺寸 1870×841，未强行拉伸至原图尺寸 |
| [design-r01/design.md](shop-xianxia/design-r01/design.md) | 功能盘点、视觉方案、组件与状态、边界及自审结果 |
| [design-r01/prompt.txt](shop-xianxia/design-r01/prompt.txt) | AI 根据用户请求整理后，实际交给图像工具的提示词 |
| [design-r01/approval.json](shop-xianxia/design-r01/approval.json) | 下一条用户指令中的母版批准原话，以及所批准文件的尺寸、哈希和范围 |

此阶段交付的是整页设计图，还不是可直接使用的独立 UI 资源。

## 阶段二：切图资源

### 用户原始提示词

> OK，该母版审核通过。现在进行切图

切图过程中，用户另有一次明确的工具选择：

> 继续仅用内置图像工具

这条回复来自 AI 关于是否允许使用本地脚本去底的询问；用户选择继续使用内置图像工具，因此后续补绘、去底均沿用内置工具。

### AI 对应操作

1. 记录母版批准，绑定具体母版文件；根据设计清单规划 19 个独立 PNG 角色。
2. 从母版裁出参考区域，保留来源坐标；使用内置图像工具分离前景、删除动态文字、补绘原来被内容遮挡的底板，并输出透明 PNG。
3. 将数量、价格、VIP 等级等留给程序显示。固定艺术字「充值」和按钮文字「贵族特权」保留在对应图片中。
4. 读取实际 PNG，检查尺寸、哈希和 Alpha；在浏览器白、暗、灰、棋盘背景下逐件查看，再放大检查代表件的边缘。
5. 选定 19 件候选，保存原始生成字节，建立资源清单、来源与提示词记录，生成自包含的逐件审核网页。

### 本轮实际遇到的问题与处理

最初，图片工具的预览显示了明显彩边，AI 将多件资源初步判为不可用，并尝试了直接透明输出、纯色底后去底、中性底后去底等路线。随后用浏览器进行真实 Alpha 合成，发现部分可疑颜色位于透明度极低的像素中：卡片、中性底购买按钮、VIP 横条的相关像素 Alpha 最高分别为 `2 / 5 / 5`，满值为 `255`。正常合成效果与工具原始预览存在明显差别。

AI 据此重新看图并修正了“全部失败”的早期判断。最终选择主面板第二轮版本、中性底购买按钮等经过实际合成检查的结果。**没有转用本地脚本去底或清理 Alpha**；本地工具仅用于参考裁切、检查、复制和预览。完整更正保存在 [STATUS.md](shop-xianxia/assets-r01/STATUS.md)。

这一轮说明：不能仅凭“文件有透明通道”宣布切图合格，也不能只看图片工具的预览就认定边缘失败，需要查看实际合成效果。

## 阶段三：网页原型

### 用户原始提示词

> OK，开始组装网页原型吧

### AI 对应操作

1. 使用 `ui-skin-prototype`，核对资源版本及哈希，将这 19 张 PNG 选入原型，保留独立运行所需的资源副本。
2. 使用 HTML/CSS/JavaScript 把面板、页签、VIP、商品卡、图标、按钮和动态文字组装为真实 DOM 组件；没有用整页母版叠加点击热点。
3. 根据图片主体范围处理透明留白，让图片的显示位置与按钮的点击区域分别计算；按压只缩放按钮内部视觉层。
4. 实现页签切换、购买确认/取消/演示完成、客服与贵族特权弹层、关闭后重开、键盘操作和状态重置。金币、体力没有商品资料，显示空态。
5. 加入标准、长文案/长数字、空商品、购买不可用四种预览状态，以及 20:9、16:9、21:9、4:3、9:16 和跟随窗口模式。
6. 在浏览器实际打开本地文件，检查默认整页、交互、按压恢复、窄屏滚动和长内容；修正窄屏 VIP 文案分行、滑动提示位置等问题。

### 操作产出

| 文件 / 目录 | 用途 |
| --- | --- |
| [prototype-r01/prototype.html](shop-xianxia/prototype-r01/prototype.html) | 可离线打开的商城交互原型，页面代码和示例数据均在文件内 |
| [prototype-r01/png/](shop-xianxia/prototype-r01/png/) | 原型实际依赖的 19 张 PNG，与切图选用版本字节一致 |
| [prototype-r01/handoff.json](shop-xianxia/prototype-r01/handoff.json) | 来源、资源哈希、布局、字体、动态字段、动作映射、实际验证范围和缺口 |
| [prototype-qa-r01/check.cjs](shop-xianxia/prototype-qa-r01/check.cjs) | 本次浏览器验证脚本，不是运行原型的依赖 |
| [prototype-qa-r01/browser-check.json](shop-xianxia/prototype-qa-r01/browser-check.json) | 已执行检查的结果，无页面脚本错误或 HTTP 请求 |
| [assets-r01/prototype-selection.json](shop-xianxia/assets-r01/prototype-selection.json) | 本条用户原话和选入原型的资源清单哈希 |

实际检查覆盖：五档商品、购买确认与取消、客服与特权弹层、Escape 与焦点恢复、页签方向键/Home 操作、关闭重开、稳定热区、移出/取消/失焦后的按压恢复、禁用态、空态、四种替代画幅、横向滚动至末档商品、重置，以及 390×844 窗口的标准和长内容布局。

横屏使用完整装饰外框；窄屏重排头部与 VIP，商品保持可读尺寸并横向滚动。窄屏外层使用程序绘制的青玉色容器，未把横版绘画强行拉长为竖版。原大厅未提供独立资源，使用中性墨青舞台承接。字体使用系统回退，跨系统可能有字形差异。

原型没有连接真实账号、支付、库存或客服服务。长内容中的大数字、高 VIP 等级和进度仅为布局压力测试。用户此条指令授权了原型组装，本文不将后续提交 Git 的要求当作原型视觉验收。

### 哪些文件需要带走

| 目的 | 所需内容 |
| --- | --- |
| 快速看整页设计 | `design-r01/master.png` |
| 给别人逐件审核切图 | `assets-r01/asset-preview.html`，图片已经嵌入，可单独离线打开 |
| 使用切图做其他实现 | `assets-r01/png/`、`assets.json`；结合 `handoff.md` 了解布局与动态字段 |
| 在另一台电脑打开网页原型 | 整个 `prototype-r01/`，直接打开其中的 `prototype.html` |
| 追溯制作过程 | 对应阶段的说明、提示词、来源记录和 `production/` |
| 在另一个项目复用换皮方法 | 项目根目录 `.agents/skills/` 中的三个 `ui-skin-*` 目录；不需要本 demo |

运行原型无需 Python、Node、构建命令、服务端或网络。制作和验证脚本另有 Python/Pillow、Playwright/浏览器等环境要求；案例中的部分 QA 脚本记录了当时机器的运行时路径，需要按本机环境调整后再复用。不要把 `production/` 的历史脚本当作必须依次运行的流水线，其中部分脚本用于重现早期诊断或拒绝覆盖已有交付。
